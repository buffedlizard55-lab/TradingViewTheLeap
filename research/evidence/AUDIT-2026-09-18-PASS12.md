## 1. Method: prove the chain with generated bars before real ones exist

The vendor is unreachable from the research sandbox and rate-limits GitHub runner IP ranges, so the
intraday capture is always the last thing to arrive. Rather than wait for it to find out whether the
downstream chain works, this pass generated captures in the exact format
`scripts/fetch_intraday.py` writes (120 series: 20 pool symbols × 15m/1h/1d), ran the whole chain
against them, then deleted them. They are **not** committed and no figure derived from them appears
in any artifact, the site, or this repository.

That run found five defects, each of which would have stopped the chain the moment real bars landed:

| # | Defect | Consequence if undetected |
| --- | --- | --- |
| 1 | `fetch_intraday.py` appended a newline to each stored capture *after* computing `stored_sha256` | every capture file was one byte longer than its own digest; `intel/intraday.py` re-hashes the file on disk, so **every** capture would have been rejected |
| 2 | The series-level raw digest was required by the loader but written by neither the document nor the index | loader `KeyError` on the first capture |
| 3 | `run_stock_competition.py` built `Series` with a non-existent keyword (`rules_cap_units`) | engine raised on its first run |
| 4 | `intel.competition.model_params_label` resolved C6–C10 through the futures parameter table | second raise, in the same run |
| 5 | `build_exec_summary.py` sent the roster's `B1` control and `S1`–`S3` baselines into `generate_stock_decisions`, and looked up their claims in only one model table | third raise; and once fixed, those usernames published an empty "waiting for" string |

Plus two correctness defects the same run exposed: the stock division's published ranking was a fixed
five rows while recommendations can reach rank 7 (the site could advise trading a username its own
ranking did not display), and the study's gap accounting assumed every session after the first yields
a gap row (it does not — the first 14 sessions have no ATR baseline yet). The accounting is now an
explicit identity, `analysed + skipped_no_atr + skipped_zero_gap == sessions − 1`, checked by the
engine and re-checked by the verifier.

## 2. Method: make the capture lane's failures visible, then fix them

Two capture runs reported green steps and committed nothing. Because GitHub serves both run logs and
uploaded artifacts from a host the sandbox cannot reach, the failure was invisible; it is now logged
as **IR-27** with both causes and their fixes.

* Cause (a): fetch and commit ran in *one* shell step. GitHub runs those with `-e`, so a non-zero
  fetch exit aborted the step before its commit helper ran — and the step still reported success
  because it was marked `continue-on-error`.
* Cause (b): `fetch_intraday.py` caught only `RuntimeError`/`ValueError`/`KeyError` per series. A
  relay answering with an HTML error page raises `JSONDecodeError`, which killed the run *before* the
  provenance index was written, leaving nothing to commit.

Fixes, all of them structural rather than cosmetic:

1. Fetch and commit are separate steps; a failed commit now fails the job.
2. Every fetch step tees its output, and `.github/scripts/capture_diagnostics.py` (always runs) posts
   the run's own evidence — index presence, per-interval captured/failed/not-attempted counts, the
   rate-limit state, non-captured series with their error text, and the log tail — as a **commit
   comment**, which *is* readable through the REST API from the sandbox, and also writes
   `data/intraday_capture_report.json` for the run to commit.
3. The per-series catch is deliberately broad, with the reason stated in the code: one bad payload
   must never cost the other nineteen series or the index.
4. Intervals run cheapest-and-most-valuable-first (long daily, hourly, then 15-minute) and each step
   carries a `--time-budget-seconds` cap, because an unbounded 15-minute sweep previously occupied the
   entire 120-minute job and committed nothing.
5. `concurrency` is `cancel-in-progress: true`: a superseded run cannot hold the single slot for two
   hours. Captures are resumable through `--only-failed`, so cancelling is strictly better than
   waiting.
6. `commit_capture.sh` refuses to commit `data/intraday_index.json` when it records zero captured
   series, because the repository reads that file's presence as "captures exist". Measured locally:
   spelling such an index into the tree and running the verifier gives **380 passed / 2 failed**
   instead of 379/0, and `scripts/refresh_artifacts.py` aborts with
   `::error::no captured intraday series available`.

## 3. Bugs fixed in the committed engine code (not just the pipeline)

* `intel/pine_emulator.py::fill_limit_order` fabricated fills. The long-side gap branch tested
  `bar.open >= level`, so a long limit the market *never reached* filled whenever the next bar opened
  above it, while a genuine gap *through* the level did not fill at all. Both directions are now
  implemented as documented (`bar.open <= level` for the gap case, `bar.low <= level` inside the bar,
  short side mirrored) with regression tests, including a never-reached-order case in both directions.
* `intel/tv_import.py` imported an empty report when a gated Performance Summary exposed no usable
  values; it now raises `ImportError_`, and unrecognised metric labels are kept verbatim *and* flagged
  in `report.warnings` rather than being silently accepted. The no-guessing contract is deliberate:
  a two-column CSV with labels this repo does not know is not evidence of a Strategy Report.
* `scripts/run_stock_competition.py` stored a wall-clock `elapsed_seconds`, which made the verifier's
  field-for-field re-run impossible by construction. Runtime now stays on stdout.

## 5. Open items carried into the next pass

1. **The intraday capture still has not landed.** The lane now commits on its own and publishes its
   evidence, but as of this commit the branch carries no `data/intraday/`. Until it does,
   `data/intraday_study.json` and `data/stock_competition_results.json` cannot be derived, the stock
   divisions render as `not_run` with the reason, and H32 stays `untested` on purpose.
2. The authenticated Strategy Report export remains blocked (no credentials are requested or held);
   the import path is proven only on the labelled synthetic fixture, and the benchmark reports
   `blocked` rather than a number.
3. The 20:1 stocks counterfactual is not an official rule set and must not be read as achievable.
4. The stock division will be fitted to one finite vendor window; no out-of-sample season exists yet.
5. Intraday bars are vendor prints with ~60-day (15m) / ~2-year (1h) retention, no bid/ask, no queue
   position and no borrow cost; latency is a measured price distance, not an executed fill.
6. The 5×/10×/20×/50×/100× targets remain measurements, not claims: the arithmetic ceiling computed
   over captured bars says 5× was not reachable in any evaluated window at the official 1:1 leverage
   and 50-unit cap.
